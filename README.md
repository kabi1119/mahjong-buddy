## 好牌，從齊人開枱開始

**v1.0.0rc1 · 朋友測試預覽版**。邀請牌友試用並回報問題；和牌自動計分尚未完成，這並非正式 1.0.0 生產版。

手機放在牌桌旁，設定四位牌友、揀莊、擲骰，再跟着俯視圖開門。**麻雀小夥伴協助真實麻雀牌局，不代替實體麻雀牌，也不會自動判斷牌局。**

深綠牌桌、奶油色牌面與一隻一索小鳥，陪你把注意力留給眼前的人。

| 一眼睇清牌枱 | 開局有條理 |
| :--- | :--- |
| **四人座位** · 暱稱與 16 款 emoji 頭像，四邊文字保持正向。 | **揀莊與門風** · 手動或隨機選莊，自動分配東南西北。 |
| **港日切換** · 香港麻雀與日本四人立直，保留同一組牌友。 | **輕巧擲骰** · 港式預設三骰／家規兩骰，立直使用兩骰。 |

## 開局輕巧，贏牌先重建

1. **齊人** — 點選四個座位，加入暱稱和頭像。
2. **揀莊** — 點選玩家或隨機揀選，確認後分配門風。
3. **擲骰** — 產生獨立骰子點數；重擲會清除上一次開門結果。
4. **開門** — 看兩個簡潔區段的指引，在實體牌牆配牌，再按「已完成配牌」。
5. **行牌** — 點牌友記錄上牌（吃牌）、碰、槓；日本模式另有立直確認。平時沒有逐次摸打或手動輪次控制。
6. **食糊（胡牌）／和牌** — 從贏家的動作選單開啟 Win flow。港式揀自摸或出銃（放槍），日本用自摸 (Tsumo) 或榮和 (Ron)，再重建手牌。可存未完成草稿、稍後續填；確認輸入不等於判定合法贏牌或計分。

> 開門以**牌牆所屬玩家的右手端**開始數，不一定是畫面右邊。圖示處理四個方向與跨角；詳細規則及家規範圍見 [規則筆記](docs/rules.md)。

## 贏牌先輸入手牌，平時專心打牌

主牌桌沒有永久的手牌輸入面板，也不要求逐次輸入摸牌／棄牌。

- **Smart Chi 上牌**：先揀上家棄牌，再看所有包含該牌的圖像順子。標出棄牌，確認手中另外兩張；赤五組成可明確指定，來源按實體座序固定。
- **碰一隻牌種就夠**：選五筒，便記錄三張五筒，毋須連按三次。
- **加槓有依據**：只可升級同局同一玩家的有效碰；確認第四張實體同牌後，保留原副露 ID，並可撤回為碰。
- **贏牌重建**：暗牌、明副露、三種槓與贏牌牌張分開輸入。港式另有八款花牌；日本依本局設定使用赤五，輸入實際寶牌／裏寶牌指示牌。
- **草稿不怕中斷**：儲存後可重開贏家動作選單 → 食糊／和牌 → 繼續草稿。重設開局或切換模式會封存舊局，不刪草稿。

程式只檢查已輸入資料的結構、張數及記錄一致性，不驗證聽牌、完整贏牌形、役、符或番數。詳見 [動作與 Hand Builder 筆記](docs/hand-recording.md)。

## 每一局，有跡可循

開局前從桌中央「牌局設定」調整家規；儲存後，香港與日本偏好各自保留。取消不改規則，還原預設須確認。本局配牌後凍結規則；點局名可看摘要及唯讀規則。頁首太陽／月亮切換淺深色，設定內可恢復「跟隨系統」。

- **港式流局**：預設冧莊（連莊），亦可選流局過莊；記錄東南西北四圈及各局，玩家實體座位不移動。
- **日本荒牌流局**：四人逐一確認聽牌／未聽牌；未回答不會當未聽牌。按人數分攤總額 3,000 點，0／4 人聽牌不支付。莊家聽牌連莊，否則輪莊；兩者都加一本場。
- **供託立直棒**：每次確認立直只扣一次 1,000 點；流局後保留供託。舊版已有立直但未扣點的牌局，須先輸入實際點數及供託對帳，不會默默補扣。未完成和牌結算前不會分配供託。
- **安全結算**：先看預覽並確認，才封存本局並產生新局 ID；可撤回最近流局，恢復莊家、本場、點數與供託。下一局已有動作／草稿時不可撤回。原定最後一局明確選擇結束或延長。
- **四槓散了／四開槓**：日本休閒家規預設啟用。至少兩位玩家合共四個完成槓後，核對第四槓已補嶺上牌、出牌、無人和牌，才確認途中流局。單一玩家四槓繼續，可能完成四槓子，但程式不自動判役滿；第五槓禁止。四槓散了不收未聽牌罰符，莊家／局數及供託不變，本場加一。

這是 **Mahjong Buddy 休閒四麻家規**，並非完全實作 WRC。WRC 2025 不承認途中流局，包括四槓散了；關閉此選項仍維持最多四槓。槓後由**王牌的嶺上牌**補一張，不是普通牌山尾或寶牌指示牌。

港式預設三骰、3 番起糊、13 番封頂、半辣上、四圈及固定八花；可選兩骰、10 番封頂、辣辣上或自訂出銃／自摸金額表。番數付款偏好供未來計分使用，現時不會自動結算。日本預設半莊、每人 25,000 點、各門一張赤五，可自訂起始點數、東風戰及赤五數量。

行牌期間底部只有「重設開局（保留牌友）」；開局前「更多」內的「清除牌友並重設」另有明確確認。兩者都保留規則偏好、歷史與草稿；取消或 Escape 不重設。

## 牌友資料，留在你的瀏覽器

**毋須登入，沒有雲端資料庫、分析追蹤或牌友資料上傳。** 暱稱、頭像、模式、開局進度、動作及贏牌草稿均透過 IndexedDB 保存在本機。Cloudflare 提供網頁檔案，仍會收到正常網頁存取請求。

資料按瀏覽器與網站來源分開：手機與電腦、localhost 與正式網址不會共享設定。清除網站資料或私隱瀏覽可能令資料消失。目前沒有雲端同步或備份；儲存失敗時，畫面會顯示提示。

## 正在成長，界線清楚

| 現在 | 計劃中 · 尚未可用 |
| :--- | :--- |
| 實體四人牌局準備、Smart Chi／加槓、Win-triggered Hand Builder、流局輪莊及點數帳本 | 香港／立直和牌自動計分、完整贏牌判定、和牌正式結算 |
| 香港麻雀、日本四人立直 | 日本三麻、台灣麻將 |
| 瀏覽器使用及 Apple 主畫面圖示 | JSON 備份匯出／匯入、完整離線 PWA 安裝與快取 |

不會偵測實體摸牌、棄牌、上碰槓、立直或食糊；只依已確認流局規則輪莊；和牌輪莊與支付尚未支援。主畫面以常見手機單屏操作為目標，短畫面、較大文字或展開設定時仍可正常捲動。

## 測試有回音

遇到問題請到 [GitHub Issues 回報](https://github.com/kabi1119/mahjong-buddy/issues)，附版本、模式、裝置／瀏覽器、重現步驟及預期結果；分享截圖前可遮去牌友資料。

日本術語：榮和 (Ron)、本場 (Honba)、供託、役 (Yaku)、飜／翻 (Han)、符 (Fu)、役滿 (Yakuman)。未來計分會區分累計役滿（累積 Han 的規則上限）與複合／多倍役滿（多個真正役滿）；兩者不同，13+ Han 並非所有規則都自動給累計役滿，WRC 2025 亦不視其為真正額外役滿。目前不提供跳滿、役滿或其他和牌分數計算。

<details>
<summary><strong>技術架構與測試範圍</strong></summary>

- **React + TypeScript + Vite**：沿用單一前端專案，桌面維持置中的 590px 手機式介面。
- **純函式規則層**：門風、骰子、牌牆幾何與狀態流程獨立於 React。
- **IndexedDB**：沿用原有資料庫與識別碼；啟動先讀取，不以預設值覆寫有效資料。
- **Vitest + React Testing Library + fake-indexeddb**：測試規則、流程、儲存、品牌與指引結構。
- **Cloudflare Workers Static Assets**：Worker `app` 提供 Vite 的 `dist/`，沒有後端 API。

自動測試採用 jsdom，不能代替 iPhone Safari、獨立顯示、鍵盤、縮放與原生對話框焦點測試。本次沒有真機或真實瀏覽器版面驗證，亦沒有製作產品畫面截圖。

完整開發、儲存行為與手動驗證清單：[開發筆記](docs/development.md)。
